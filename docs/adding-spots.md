# スポットの追加方法（data/areas/）

よりみっけに新しい場所を登録するときの手引きです。2026年9月時点の実装に基づいています。

---

## 1. ファイルの構造

スポットは **市ごとに1ファイル** で `data/areas/` に入っています（2026年9月に `data/spots.json` 1本から分割）。

```
data/areas/
  common.json     ← 全体の出典の説明と日付（スポットは入っていない）
  kochi.json      ← 高知市 43件
  hiroshima.json  ← 広島市 75件
  ibusuki.json    ← 指宿市 33件
  matsue.json     ← 松江市 46件
```

街のファイルの中身:

```json
{
  "area": "松江市",
  "prefecture": "島根県",
  "addedAt": "2026-09-21",
  "source": "この街だけの出典の説明（空でもよい）",
  "statsByPrefecture": {
    "島根県": { "total": 46, "kunishitei": 23, "kenshitei": 12, "note": "収録件数" }
  },
  "spots": [ /* ここにその街のスポット */ ]
}
```

`lib/spots.ts` が起動時に全部の街を読んでまとめます。合計件数（画面の「話しかけられる197か所」）は自動で数えられます。

**重要**: スポットを足したら、その街のファイルの `statsByPrefecture` の `total`（指定文化財なら `kunishitei` / `kenshitei` も）を直してください。ホーム画面の「国の指定文化財 55件」はこの数字の合計です。放置すると画面の数字が嘘になります。

## 2. 1件分のフォーマット

高知城の実データが、いちばん良いお手本です。

```json
{
  "id": "kochi-castle",
  "name": "高知城",
  "icon": "🏯",
  "prefecture": "高知県",
  "city": "高知市",
  "designation": "国指定重要文化財・史跡",
  "category": "城郭建築",
  "era": "江戸時代（1603年築城、1747-1753年再建）",
  "address": "高知県高知市丸ノ内一丁目2-1",
  "lat": 33.561375,
  "lng": 133.529541,
  "grounding": "土佐藩初代藩主・山内一豊により1603年に築城された平山城。…",
  "sources": [
    "高知城管理事務所 案内資料",
    "文化庁 国指定文化財等データベース"
  ],
  "access": "（任意）一般の人がどう見学できるか"
}
```

## 3. フィールド仕様

| フィールド | 必須 | 型 | どこで使われるか | 書き方の注意 |
|---|---|---|---|---|
| `id` | ✅ | string | 内部の参照キー。ルート案内はこのIDでスポットを指す | **全件で重複禁止**。半角英数とハイフンのみ。一度公開したら変えない（変えると既存のルートが壊れる） |
| `name` | ✅ | string | 画面表示、AIプロンプト、ルートの抽出 | **AIが返した文章から名前を照合している**ので、正式名称そのままにする。括弧や中黒を勝手に増やさない |
| `icon` | ✅ | string | 地図のピン、一覧、詳細画面 | 絵文字1つ。写真は使わない（著作権回避の方針） |
| `prefecture` | ✅ | string | エリア判定、統計 | 「高知県」のように「県」まで |
| `city` | ✅ | string | AIが「どの街の案内人か」を決める根拠 | 「高知市」のように「市」まで |
| `designation` | ✅ | string | 一覧・詳細のバッジ、地図のピン優先度 | 「国指定重要文化財」「県指定史跡」「指定なし」など。**「国」「重要」「史跡」などの語で地図の表示優先度が決まる**ので、正式な指定名称を書く |
| `category` | ✅ | string | 詳細画面、営業時間の推定 | 「城郭建築」「古墳」「神社」など。**`lib/visit-hours.ts` がこの語から見学時間を推定する**（寺・神社→日中、資料館・城→施設時間、跡・碑・樹→時間制限なし） |
| `era` | ✅ | string | AIプロンプト | 「江戸時代（1603年築城）」のように、時代＋年があると解説の質が上がる |
| `address` | ✅ | string | 詳細画面、AIプロンプト、距離表示 | 番地まで。公表されていない場合は字までで可（その旨を `access` に書く） |
| `lat` | ✅ | number | 地図、距離計算、ルート探索 | 緯度。日本国内なら **24〜46** の範囲。小数6桁程度 |
| `lng` | ✅ | number | 同上 | 経度。日本国内なら **123〜146** の範囲。**latとlngを逆にする事故が一番多い** |
| `grounding` | ✅ | string | **AIが話す内容の唯一の根拠** | ここが本体。100〜250字程度。AIはこの文章を材料に喋るので、ここが薄いと答えも薄くなる |
| `sources` | ✅ | string[] | 詳細画面の出典表示、AIの「（出典: …）」 | 1件以上。2件あると望ましい。URLを含めてもよい（読み上げ時は自動で除去される） |
| `access` | 任意 | string | 詳細画面「一般見学について」、**営業時間表示の第一根拠** | 「常時見学可能」「開館時間は要確認」など時間に触れると、推定ではなく確定として扱われる（後述） |
| `facilities` | 任意 | object | 詳細画面の設備バッジ | `{ "toilet": true, "parking": true, "shelter": true, "indoor": true }`。**true だけを書く**。「無い」と断言するには現地確認が要るので、不明は書かない |

## 4. `grounding` の書き方（ここが一番大事）

AIはこの文章だけを見て喋ります。Wikipediaを検索するツールも持っていますが、それは補助です。

**良い例**（高知城・実データ）:
> 土佐藩初代藩主・山内一豊により1603年に築城された平山城。1727年の大火で追手門以外の建物の大半を焼失し、1747年から1753年にかけて再建された。天守・本丸御殿（懐徳館）・追手門など本丸の建造物群が現存する全国的にも希少な城で、天守と本丸御殿が両方残るのは高知城のみ。

固有名詞・年号・「〜のみ」という特異点が入っていて、AIが語れる素材が多い。

**避けたい例**（現データにも残っている）:
> 個別調査・住所照合済み

これは調査メモであって解説ではありません。この状態のスポットは、話しかけてもAIが何も語れません。現在31件が60字未満です。

**チェック**: 「その場所の前に立った人に、これだけ読んで面白いか？」

## 5. `access` と営業時間の関係

`lib/visit-hours.ts` が次の順で判定します。

1. **`access` に時間の記述がある** → それを根拠として採用（画面に「目安」と付かない）
   - 「開館」「休館」「営業」「予約」「拝観時間」等を含む文 → **施設の時間内**
   - 「常時」「随時」「自由に見学」等を含む文 → **時間の制限なし**
2. **記述がない** → `name` と `category` から推定（画面に「（目安）」と付く）

つまり、**`access` に一文足すだけで推定が確定に変わります**。

```json
"access": "屋外から常時見学可能。安全のため建物内部への立ち入りはできない。"
```

## 6. 追加の手順（GitHubのWeb画面から）

1. GitHubでリポジトリを開く → `data/areas/<その街>.json` → 鉛筆アイコン（Edit）
2. `"spots": [` の中の、**最後の `}` の後ろにカンマを足して**、新しいオブジェクトを貼る
3. 同じ編集画面で `statsByPrefecture` の `total` を +1（指定文化財なら `kunishitei` / `kenshitei` も）
4. Commit changes → コミットメッセージに何を足したか書く
5. Vercelが自動デプロイ。**「Redeploy」は使わず**、デプロイ一覧のコミットハッシュが自分のコミットと一致しているか確認する

JSONは1文字の間違いでアプリ全体が起動しなくなります（壊れたのがどの街のファイルかはビルドのエラーに出ます）。**貼り付け後、GitHubの編集画面のまま以下を目視確認**してください。

- 直前の要素の後ろにカンマがあるか
- 自分が足した要素の後ろには**カンマがない**（配列の最後の場合）
- 引用符が全角「”」になっていないか（コピペ事故の定番）

## 7. 追加前のチェックリスト

- [ ] `id` が他の街も含めて既存のものと重複していない（重複すると後から読んだほうが無視される）
- [ ] `city` がファイルの `area` と同じ表記になっている
- [ ] `lat` / `lng` が逆になっていない（緯度33付近・経度133付近が高知）
- [ ] 地図で座標を確認した（Googleマップに `33.561375, 133.529541` と貼れば確認できる）
- [ ] `grounding` が60字以上あり、年号か固有名詞が入っている
- [ ] `sources` が1件以上ある
- [ ] `name` が正式名称（AIの返答から名前照合するため）
- [ ] `statsByPrefecture` を更新した
- [ ] 写真を使っていない（著作権方針。アイコンは絵文字のみ）

---

## 8. やってはいけないこと

- **`scripts/ingest-data.mjs` と `scripts/build-spots.mjs` を実行しない**。どちらも分割前の `data/spots.json` 1本を前提に書かれていて、今の構造では正しく動きません（`ingest-data.mjs` は既存データを上書きして消します）
- **`id` を後から変更しない**。案内中のルートが参照できなくなります
- **記号系の絵文字は異体字セレクタ付きで書く**（`⛩️` `⛰️` `⚔️` など。付けないと環境によって白黒の文字として描かれる。既存151件は統一済み）

## 9. 既知の課題（余裕があるとき用）

| 内容 | 件数 | 影響 |
|---|---|---|
| `grounding` が60字未満 | 31件 | AIがほとんど語れない |
| `grounding` が調査メモのまま（「個別調査・住所照合済み」） | 数件 | 話しかけても中身がない |
| `id` と `name` が対応していない（例: `godaisan-hitsuzan` が要法寺） | 数件 | 動作に支障はないが、保守で混乱する |
| ~~絵文字の異体字セレクタ混在~~ | 解消済み（38件に U+FE0F を付与して統一） | — |
| 営業時間の実データがない | 全件 | 現在は屋外／施設／要確認の3分類で代替（`lib/visit-hours.ts`） |

## 10. 新しい街を足す手順

1. `data/areas/<街の英字名>.json` を1章の形で作る（`prefecture` は「県」まで、`city` と `area` は「市」まで）
2. `lib/spots.ts` の先頭に `import xxx from "@/data/areas/<街>.json";` を足し、`AREA_FILES` に `xxx` を加える
3. 同じファイルの `KNOWN_AREAS` にその街の中心座標を1行足す
4. 既定の街（位置情報がないとき最初に出す街）を変えたいときは `FALLBACK_AREA` と `FALLBACK_CENTER` を書き換える

ある街のデータに問題が出たら、`AREA_FILES` からその街を外せば、他の街はそのまま動きます。

`grounding` が短いスポットも登録できます。AIは足りない情報を `searchWikipedia` で補って答えますが、根拠の中心は `grounding` なので、書ける範囲で充実させてください。

## 11. 端末に保存しているもの（参考）

データを足す話とは別ですが、動作を追うときに必要なので記しておきます。すべて
その端末の localStorage のみで、サーバーには送っていません。

| キー | 中身 |
|---|---|
| `hh-settings-v1` | 設定（ミュート、音声、屋外モードなど） |
| `yorimikke-onboarded-v1` | はじめての案内を見たか |
| `yorimikke-route-v1` | 作ったルート・移動手段・何番目の区間まで来たか（18時間で失効） |
| `yorimikke-area-v1` | 位置情報が使えないときに手で選んだ街 |
| `yorimikke-visited-v1` | 訪問済みスポットと、最初に訪れた時刻 |
